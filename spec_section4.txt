endpoint; store the raw file in object storage; create a `source_documents` row.\r\n2. **Text Extraction** — PyMuPDF 
extracts text from text-native PDFs. Pages returning little/no extractable text are flagged and routed to an OCR 
fallback, with OCR confidence stored per page.\r\n3. **Structural Segmentation** — Detect article/section/clause 
boundaries via numbering and heading patterns; persist as ordered `document_sections` rows with a human-readable 
reference label.\r\n4. **Context-Aware Chunking** — Group sections into LLM-context-sized chunks, preserving section 
boundaries with light overlap so no obligation spans an undetected chunk break.\r\n5. **Requirement Extraction** — 
Each chunk passes through: classify content type → extract structured fields per the requirement schema → compute a 
confidence score.\r\n6. **Deduplication & Cross-Referencing** — Compare new requirements against existing ones via 
embedding similarity to flag duplicates and cross-regulation overlap candidates.\r\n7. **Validation Routing** — 
Requirements below a confidence threshold, or above a severity threshold, route to `pending_review`; only 
human-approved requirements can reach `approved`/`enforceable`.\r\n8. **Policy Compilation** — Approved requirements 
for a regulation version compile into a versioned policy package — this is what the Developer API serves.\r\n\r\n## 7. 
LLM / AI Architecture\r\n\r\n- **Staged extraction, not single-shot** — classify → extract → score as separate stages, 
each independently verifiable, rather than one prompt doing everything.\r\n- **Schema-constrained output** — use the 
provider's structured-output/function-calling mode so extraction results are always valid against the requirement 
schema.\r\n- **Confidence scoring** — combine model-reported confidence with rule-based checks (required fields 
present, severity within the allowed enum, references resolve to a real section) into a final score used for 
validation routing.\r\n- **Model routing** — a smaller/cheaper model for classification and triage; the strongest 
available model for structured extraction, where accuracy matters most.\r\n- **Retry & repair loop** — on schema 
validation failure, re-prompt with the validation error before falling back to human review.\r\n- **Embeddings** — one 
per requirement, stored via pgvector, powering duplicate detection, semantic search, and the future cross-regulation 
conflict-detection phase.\r\n\r\n## 8. Rule Versioning & Diff Engine\r\n\r\n- Each ingested amendment creates a new 
`regulation_versions` row under the same parent `regulations` row.\r\n- Diffing happens at the requirement level, not 
raw text: match requirements across versions by semantic similarity plus section reference, then classify each as 
added, removed, or modified.\r\n- A modified requirement retains both old and new structured objects so the diff view 
can show field-level change (e.g., severity moved from medium to high).\r\n- Diff summaries generate automatically on 
version creation and feed both the \"what changed\" dashboard view and the impact analysis engine below.\r\n\r\n## 9. 
Compliance Impact Analysis Engine\r\n\r\n- Organizations map internal systems/APIs to specific requirement IDs via 
`system_mappings`.\r\n- When a requirement is added, removed, or modified, the engine looks up every `system_mappings` 
row referencing that requirement ID and generates an impact record.\r\n- Impact records feed the \"affected systems\" 
dashboard view and can trigger a webhook/notification to the org's registered endpoint.\r\n- Impact severity inherits 
from the requirement's severity, with an org-level override allowed.\r\n\r\n## 10. Developer API\r\n\r\nVersioned

Jobs & Async Processing\r\n\r\n- Recommended queue: Celery with Redis as broker — keeps ingestion, monitoring, and

inspection.\r\n\r\n## 12. Regulatory Monitoring Service (Phase 3 groundwork)\r\n\r\n- A scheduled worker polls

same pipeline used for manual uploads.\r\n- Sources without a machine-readable feed fall back to scheduled re-scraping

alone would miss.\r\n\r\n## 14. Reporting Engine\r\n\r\n- Report types match the PRD: executive summary, technical

is a developer platform that ingests legal and regulatory text — GDPR, HIPAA, the EU AI Act, SOC 2, ISO 27001, DORA, 
PCI DSS, and future frameworks — and automatically converts it into structured, machine-readable, API-enforceable 
compliance policy. It replaces the current manual chain (law firm interpretation → compliance review → internal 
meetings → manual engineering implementation → audit-time gap discovery) with an automated extraction-to-policy 
pipeline, collapsing time-to-compliance from months to minutes.\r\n\r\n## 2. Problem Statement\r\n\r\nGovernments 
publish thousands of pages of new and amended regulation every year. Today's compliance path is manual at every 
stage:\r\n\r\nGovernment publishes regulation → Law firms interpret it → Compliance team reads it → Internal meetings 
→ Engineers manually implement controls → Audits discover gaps months later.\r\n\r\nThis process is slow, expensive, 
inconsistent across teams, fully human-dependent, and error-prone. Organizations routinely operate out of compliance 
for weeks or months without realizing it.\r\n\r\n## 3. Why Now\r\n\r\nRegulatory output — AI-specific regulation in 
particular — is accelerating faster than compliance teams can manually track it. Policy-as-Code and 
Infrastructure-as-Code are already standard engineering practice, but no equivalent layer exists for regulation 
itself. Regulation-as-Code Compiler is the missing translation layer between published legal text and the 
software-enforceable policy that Policy-as-Code tooling expects as input.\r\n\r\n## 4. Goals & Success 
Metrics\r\n\r\n**Primary goal:** collapse the time between a regulation's publication and an organization's 
enforceable, machine-readable compliance posture — from weeks/months to minutes/hours.\r\n\r\n**Supporting 
goals:**\r\n- Replace ad hoc manual legal interpretation with structured, repeatable, auditable extraction for 
baseline obligations.\r\n- Produce compliance policy that engineering systems can consume directly (APIs, rule
